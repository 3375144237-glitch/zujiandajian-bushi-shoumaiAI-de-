# 从设计稿搭建组件库：操作手册

每步先处理一个代表组件，通过后再批量搭建。可用 Figma 的图层、设计、资产和原型面板操作；由 Codex 执行时优先使用获授权的 Figma 读写和导出工具。下列 API 名用于映射操作，以当前插件接口及工具能力为准。

先按[组件资产准入与复用验收](asset-contract.md)确定资产与示例边界，并记录每组接口。画布结构可预建；成品说明和场景在代表母版的真实复用通过后完成。

## 1. 定位定稿、目标与基线

1. 打开用户提供的链接，记录文件、页面、画板或节点 ID，区分业务定稿、组件库、独立预览和原型。按项目约定读对应评论；读不到时记录限制，继续核对可见设计。只有截图时，测量只作几何参考，字体、变量和交互标待核。
2. 为每个目标找真实用例：优先选择默认态、结构有变化的状态、窄宽或长文案各一例。先保存原始宽高和导出基线；需要看浮层时同时保留整张画板和局部画面。
3. 查写入影响。Figma 选实例用「Go to main component」定位母版；程序用节点 ID 和 `getMainComponentAsync()`，对子层实例递归查。改母版前从定稿和已知消费者反查引用；改样式或变量还要查别名、模式及受保护节点实际使用的资源。无法查证跨文件影响时用独立资产，验证副本已解除对待改资源的依赖。保存待改节点 ID、旧值及定稿引用作为回归和回滚依据。

**通过条件：** 每个目标都有可追溯的对照和明确的写入位置。缺某一态的证据时只标该项，其他可继续。

## 2. 盘点资产并决定复用方式

1. 查 Assets、启用的 Libraries、Variables、文字与效果样式。搜索用途和同类资产，在原稿选图层检查它是 Frame、Component、Component Set 还是 Instance。定位母版，确认业务实例的实际属性值。
2. 展开组件集，记录真实存在的属性组合和嵌套来源。按「用途 × 布局条件 × 有效状态」逐项对照；属性菜单出现某个值，不代表它在各尺寸都存在。只查目标范围。
3. 同用途同结构就复用；有母版缺有效状态，补原组件集；只有场景示例不足，用已有实例补预览。确有独立复用或维护需求时再建母版。合并前查实例、链接和独有内容；保留可用原节点。

**产出：** 每组一行 `用途 | 定稿节点 | 当前母版 | 已有状态 | 缺口 | 复用/补建决定`。

## 3. 从样例提取组件规格

1. 从原稿设计面板逐层读取：文案、容器宽高和最小限制、内外间距、对齐、裁切、字体和数值字重、行高、填充开关、透明度、描边对齐、圆角及效果。按尺寸逐档核对圆角、字重和换行，不从大号等比推小号。再量目标和相邻控件的位置，明确哪些尺寸属于组件，哪些由宿主控制。浮层按绝对位置与叠放找到实际面板，和触发器分别读数；用导出核对两者各自的可见边缘。
2. 给差异分类。可编辑同一段内容用 Text；可选图层用 Boolean；同一位置替换图标或子控件用 Instance swap 或受支持的 Slot。尺寸、职责或交互状态让样式或结构发生一致变化，才用 Variant；职责不同或是完全不同的布局，再考虑拆组件。状态决定的提示文字保留在对应状态。
3. 对照现有变量和文字、效果样式：同用途且各模式正确就复用；同色不同用途不强绑。核对 Alpha 所在层级，区分只淡化背景与连内容一起淡化。仅为明确用途补缺少的变量或样式。对每个状态记录触发原因、可共存项、优先级、保留内容、可用动作和恢复方式；定稿未画出的有效组合标「设计补充」。

**产出：** 组件层级树、有效状态矩阵、默认值、各轴尺寸策略、规格对应的参考节点。

### 动手前定画布与场景

1. 先建导览、基础规范、组件目录、场景示例的 Figma 页面或编号区段；小库可单页分区，大库按组件家族分页。导览写范围、如何插入实例、从哪个场景开始，并链接到各区。基础规范放实际色板、文字层级、间距和尺寸；有变量时用变量绑定色板。
2. 决定并沿用同一左边线、栅格、栏宽和间距。组件卡依次使用「名称与用途说明｜母版及变体」；母版与用法放同区，旁边不另铺一条无说明的重复实例列。说明用固定栏，组件示例按实际宽高安排，宽组件独占一行、不同高度顶对齐；按内容实际高度计算下一组位置。保留清楚的区域间距和层级。
3. 先做场景清单：`用户任务 | 触发条件 | 原稿和宿主尺寸 | 使用组件与选值 | 预期呈现与检查点 | 原稿对照/设计补充`。默认从主流程、确有差异的状态以及与尺寸相关的边界中选代表样例；避免凑横向组合。不确定的产品行为写「待核」，不从画面发明规则。

## 4. 搭一个能伸缩的基础母版

1. 在获授权页面新建 Frame，或把原稿中的视觉结构复制到独立搭建区。先放通用结构，图标和子控件从 Assets 拖实例。按职责命名子层，例如 `Content`、`Leading`、`Actions`。
2. 选同组图层按 `Shift+A` 应用 Auto Layout。先设方向、对齐、间距和内距；再分别设横纵两轴：规格固定用 Fixed，随内容用 Hug，占剩余空间用 Fill。需要换行的文字先确定可用宽度，再启用自动高度。等分列用结构相同的列容器；避免让同轴 Hug 父框依赖 Fill 子层反向决定宽度。用 API 时先把子层放进自动布局父框，再设 `layoutSizingHorizontal/Vertical`。
3. 在设计面板绑定变量和样式，切换实际模式读回；通过 API 为填充或描边绑定变量时，用 `figma.variables.setBoundVariableForPaint` 生成新 Paint，再赋回图层。使用 `loadFontAsync` 加载待改文字的字体和字重；混合样式按受影响文字范围加载。
4. 用「Create component」或 `figma.createComponentFromNode` 创建母版。由 Assets 拖实例或用 `createInstance()`。先在原稿宽度还原默认态，再放到窄、宽业务父框实测相邻位置及文字断行。测试宽度来自目标稿或实际内容极限。

**通过条件：** 新实例链接正确，默认态和宿主内的布局均通过。基础布局不稳时先修母版，再加变体。

## 5. 加属性、变体和必要的原型行为

1. 选母版里的文字、可选层或嵌套实例，在设计面板分别新建并连接 Text、Boolean、Instance swap。需要隐藏后回流时，将 Boolean 连到参与布局的包裹层；使用 Slot 前先验证环境支持、实例可替换。API 用 `addComponentProperty` 建属性，并将返回的键连接到对应子层的 `componentPropertyReferences`。
2. 从已验的母版新增有效变体。已有组件集用「Add variant」或在原集合内补缺；独立组件首次成组用「Combine as variants」或 `figma.combineAsVariants`。按定义好的维度和取值命名，检查无重复组合。维护时保留母版 ID、属性键和消费者绑定。
3. 在实例先改文案、换图标、关闭可选层，再做 A → B → A。对有效叠加另测「开独立条件 → 切主状态 → 关独立条件 → 恢复」，检查可见层、同一视觉通道的优先级、可用动作及宽高。互斥状态只提供合法选项。核对业务覆写保留，状态专属文字正确变化。API 用实际属性键调用 `instance.setProperties`，再读回 `variantProperties`、子层及引用。
4. 仅需求包含原型时，到 Prototype 面板设触发与目标，实测进入、切换、退出。真实保存、权限、异步重试等由产品环境验证。
5. 每组完成即写组件或组件集 Description，再写同区可见说明：用途与不用条件、属性名和选值（含常用默认）、尺寸/宿主/内容约束、需要搭配的组件、原稿链接。按阅读顺序排实际变体，让标签与图形一一对应；超宽先分行，再设置组件集外框并写入子坐标。移动已有母版前核对引用与原尺寸；为 Fill 型母版保留等宽承载框，或在独立容器内保留其几何，随后读回母版及现存实例的实际尺寸。

**通过条件：** 新实例和已有预览都能按要求切换，文案、显隐和图标正确。

## 6. 放回业务场景

1. 按场景清单复制实际业务行、整栏或画板到独立预览。先记宿主尺寸、局部位置、内容和遮罩，再用 Swap Instance 或插入新实例替换目标。保留相邻控件、业务数据和父框约束；仅复制画板、贴截图或平铺通用状态不能算业务场景。
2. 同一任务按原稿顺序并排或逐步展示，例如默认 → 操作 → 反馈，或窄栏 → 展开。至少一例体现有意义的差异；按证据选长文案、边界宽度、可选内容或异常，无需强制全组合。注明「原稿对照」或「设计补充」，后者仅补使用规则或实例装配，不能写回定稿。不要用事实未明的数据或业务逻辑填空。
3. 每个场景现场标注「何时出现、使用哪些组件/取值、需核对的结果」，附原稿和相关母版或组件章节入口。把标题、说明、宿主固定在同一个可复制的示例框，按真实宽度排版，不缩放实例。已有场景优先就地整理；回看父框约束、实际高度、阴影、相邻位置和实例原链接。

**产出：** 可编辑的场景实例、可对照的默认态、代表变体和边界宽度预览。至少在一个新宿主里使用不同的业务内容或依赖验证同一母版的复用，不能只在原画板副本里替换成同样的数据。

## 7. 自验、修复、交付

1. **读回结构。** 验母版 ID、实际变体、属性键、嵌套来源、变量模式和可见文字。验证定稿属性及引用与基线一致。工具超时先读已写入的结果，只补缺项。
2. **实测布局。** 在业务宿主改宽、改长文案、切状态和显隐，核对相邻控件坐标、内外间距、列对应和裁切。用可观察条件判断，例如「隐藏图标后不残留空隙」「切回原状态时自定义标题保留」。
3. **看实际导出。** 导出入口、每个组件章节和业务场景组；总览查对齐、密度和阅读顺序，局部原尺寸查说明换行、变体标签、过宽组件及遮罩。以原稿同尺寸同倍率对照宿主，区分设计裁切、滚动和意外越界。模拟首次使用：从导览找到组件，按说明选对变体，再从场景复制可编辑实例并读回母版链接。未完成这条路径的组件库不算验收通过。只有做过像素比对且一致才称逐像素一致。
4. **修完复验。** 重跑原失败用例，再检查受影响的母版、已有实例和相邻内容。全库任务逐组扫变量样式、组件、预览、文档及链接；局部任务限于影响范围。链接去重后实际读取目标。两次针对同原因的修复无进展，保留最后可用版本、记录阻塞并继续其余部分。

**交付条件：** 画布导览可用，说明和母版同区，每个主要家族有可复制的场景，状态标签与实际实例相符，已发现且可修的差异均闭环。给入口、重要章节、代表场景链接和验收例外。无导出条件标「属性已核，渲染待验证」；无产品运行环境标「静态设计已验，真实交互待联调」。不要求用户重复验收。
