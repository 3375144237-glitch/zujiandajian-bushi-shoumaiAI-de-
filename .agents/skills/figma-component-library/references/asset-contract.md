# 组件资产准入与复用验收

### 1. 决定什么进入资产库

1. 按「原稿用例 → UI职责 → 可复用对象」列清单。写出两个实际用例，或一个已确认的独立复用理由。一次性业务数据、截图、画板和凑齐分类的控件放到参考或暂缓；不要把请求复杂度当作新建理由。
2. 把产出按功能分成四层：Foundations 是由资产消费的颜色、字型、边框、间距和效果；Components 是独立可插入的母版或组件集；Patterns 是用真实实例搭起来的业务组合；References 放真实原稿、场景和不同状态的证据。同页时也要可区分。先录资产依赖关系，按基础控件 → 复合组件 → 布局组装的顺序写入。
3. 查 Figma Assets、母版、变体实例和变量引用。缺资产才新增；缺属性或有效状态在原资产补；已有可复用资产但缺证明就补实例用例。更换同用途资产前查依赖和覆写；避免并列两套推荐入口。

### 2. 定义并实现母版接口

1. 每组先列一行：`规范名 | 参考节点 | 职责和不适用 | 子资产 | 公开属性和默认 | 有效变体 | Fixed/Hug/Fill 与边界 | 新场景验收`。先区分固定的结构、由状态决定的内容、由场景决定的数据。
2. 用 Text 暴露可改的标题、表值、输入值；用 Boolean 暴露可选图层并验证关掉后的回流；用 Instance Swap 或 Slot 暴露图标、可替换内容、列或行。通过 `addComponentProperty` 和子层 `componentPropertyReferences` 实际接线；支持的嵌套暴露接口优先用于高频项。普通固定标签和视觉结构无需全量暴露。
3. 同一槽位的多个图标、数据和字段名都不是变体。只在有一致的布局、样式或交互状态变化时建轴。把状态分为互斥选项和可同时生效的条件：可独立显隐的视觉层可用 Boolean；确实改变同一组样式或结构时，只建有依据的组合，并声明优先级。跨变体保持同义属性键和一致的图层角色；状态本身决定的标签不共享动态数据键。
4. 表格优先确定重复的列、行、单元格、数据区与反馈区，确有复用再抽母版。列定义要与行对齐；业务词和数字从实例输入，固定列与状态区能组合。弹窗优先确认外壳的标题、正文、底部动作边界；当正文有多个可独立替换的用途，暴露可交换实例或插槽。父级在流程图标注行为，母版保留布局约束。
5. 先用临时实例探测「能绑定」和「能覆写」。绑定后比对文本各范围的字体与色值；必填星号等语义不同的字符应与可改文案分层，不能因属性绑定而统一着色。多变体原先文案不同时，先验证共享 Text 默认值会不会改写其他变体；固定状态标签独立，业务例文放实例。字体不可用时保留原字型，按授权尝试其他编辑环境；只报接线成功、原字型覆写未验。

### 3. 实际使用才通过

1. 为每个主要家族从资源页插入临时新实例；工具可用 `createInstance()`，然后回读 `getMainComponentAsync()`。在一块从零创建的框内组装，不从预览复制已有覆写充当测试。真实实例名称、节点宽高、发生变化的文案、链接和截图应可核对。
2. 按资产用途验证：文字用两组真正不同的内容，测长短与保留；可选部分测关→开和间距；插槽换两个内容源；状态变体做 A→B→A；伸缩组件测两个关联宽度。按需要覆盖，不给只固定一种规格的图标强加宽高变化。确认真实消费变量或样式；回归旧实例与同尺寸定稿。
3. 在场景里测试一条业务流程及至少一个会改变选型的分支，写明触发条件、资产组合、期望结果与出处。未有定稿证据的延展标「设计补充」，未完成的产品行为标「待核」。这是库的使用证据，不计入资产数。
4. 所有适用项通过才标该家族可复用。实际绑定、实例覆写、调宽、真实渲染、产品交互和跨文件可用性分别报结果。若明确获得发布权限，发布后在另一份测试文件启用团队库、插入和修改一个新实例，验证变体及依赖可用；单文件环境只报本地组件库。
