# Figma 组件库搭建

适用于有设计稿或已有组件库的项目。技能只保存取证、搭建和验收方法。每次从用户确认的当前项目来源采集规格；技能正文、引用和模板不得保存项目名、文件链接、图层 ID、实际文案或素材，以及色值、圆角、字号、间距等设计值。具体证据写入当次项目交付。先读当前工作区规则和问题日志（若有）；后者用于排障，项目案例只有在本次被确认适用时才可引用。截图只能证明可见表现；证据不足标「待核」，经授权的延展标「设计补充」。

1. 搭建、整理或补齐任务先读[搭建与自验手册](references/build-workflow.md)和[组件资产准入与复用验收](references/asset-contract.md)。先区分「只读分析」「仅提取 Foundations」「实际搭建／修正组件」；执行到用户指定的阶段为止。提示词、旧规范和附图按任务中指定的用途使用，不能自行扩大写入范围。
2. 企业后台需要结构化规范、分阶段写入，或补齐尺寸、交互状态和业务场景时，读[企业后台变体与场景手册](references/b2b-variants.md)。先建立覆盖矩阵，再逐模块写入；获授权但未经原稿证实的扩展独立标为「设计补充」。
3. 布局、字体、颜色、浮层、变体切换或工具写入出现偏差时，用[常见难点与解决方法](references/troubleshooting.md)定位、修复、复验，把预防措施用于下一批组件。
4. 定稿默认只读。改母版、变量、共享样式或交互前查直接、嵌套及共享引用；不能证明修改范围安全时用独立资产，无法隔离时暂停该项。只在获授权的目标写入；搭建权限不包含发布库权限。

## 一次任务交付到可用

- **先交付资产，再证明用法。** 在全新空白验证框里，从资源中新插入一个母版实例，换成不同的业务内容或实例依赖，按有意义的宽度与状态切换，检查实例未分离、布局回流、覆写保留。绑定和覆写要分别验证。仅画板成组、原图升格为组件、实例链接存在或状态能切换，均不足以算可复用。
- 完整库区分基础规范、原生母版、实例组合、原稿证据和使用文档，独立建页或同页分区以项目约定为准。缺属性补原资产；缺场景补预览；确有独立复用职责才新增母版。示例不计为母版。
- 在 Figma 内提供可浏览的入口、基础规范、组件说明和可复制的实例。样例与母版靠近；并排时可左放用法与对照、右放原生母版与带标签的变体。独立母版注明类型。完整交付时，为约定的 Docs 或等价区域填好上手步骤、组件与场景索引、复用验收及范围说明；仅建骨架时不提前写入。
- 每个主要组件家族至少进入一个真实宿主。按原稿中有意义的条件增加对照，例如窄宽、流程反馈或空态；优先示范会改变布局或操作的差异。用有母版链接的实例组成场景，标明原稿对照、设计补充和未实现行为。
- 交付前逐页回读实际内容，导出入口、文档、各组件章节和各场景组，核对链接目标、文字可读性及裁切。按首次使用路径实走「找到组件 → 选变体 → 插入或复制实例」。空页只能标为骨架；组件搭建完成不能代替完整交付验收。

- 收到「搭建／修正／补齐」后，在同一轮任务内完成盘点、写入、实例测试、导出比对、修复与复测。能从证据推断或能自行修正的事项直接处理，不把常规验收交回用户，也不为每一批修改停下来等确认。
- 大量修改按组件家族分批。每批读回母版、试插实例、与原稿导出对照，修复后再进下一模块；断线或超时先查已成功的节点，再补缺项。两次针对同一原因的修复无进展，保留最后确认可用的版本，继续不相关工作。
- 缺文件权限、缺字体或渲染环境、定稿证据冲突等明确阻塞单列。未实际覆写过的 Text 不标通过。明确交付的是本地资产，还是已发布且在另一份文件中实际插入过的团队库；不以“可发布”冒充已发布。
