# Figma 组件库搭建

适用于有设计稿或已有组件库的项目。颜色、字型、尺寸、主题和状态以目标项目为准。先读当前工作区规则和已有问题日志（若有），再以用户确认的定稿、设计系统及评论为证据。截图只能证明可见表现；无法读到的属性和未画出的交互分别标为「待核」与「设计补充」。

1. 搭建或补齐任务先读[搭建与自验手册](references/build-workflow.md)，按「定位与基线 → 盘点 → 定义规格 → 搭母版 → 加属性与变体 → 组装 → 自验与交付」执行。每步都有具体操作和验收条件。只读验收执行对应的盘点与自验步骤，不写入。
2. 布局、字体、颜色、浮层、变体切换或工具写入出现偏差时，用[常见难点与解决方法](references/troubleshooting.md)定位、修复、复验，把预防措施用于下一批组件。
3. 定稿默认只读。改母版、变量、共享样式或交互前查直接、嵌套及共享引用；不能证明修改范围安全时用独立资产，无法隔离时暂停该项。只在获授权的目标写入；搭建权限不包含发布库权限。

## 一次任务交付到可用

- 收到「搭建／修正／补齐」后，在同一轮任务内完成盘点、写入、实例测试、导出比对、修复与复测。能从证据推断或能自行修正的事项直接处理，不把常规验收交回用户，也不为每一批修改停下来等确认。
- 大量修改按可验证的小批执行。每批读回母版及实例后再扩大；断线或超时先查已成功的节点，再补缺项。发现可复现差异就修复并重验受影响范围。两次针对同一原因的修复无进展，保留最后确认可用的版本，继续不相关工作。
- 缺文件权限、缺字体或渲染环境、定稿证据冲突等明确阻塞单列。说明涉及节点、已查证据和缺少条件；未验项不标通过。交付组件和实例预览链接、已验范围及仍需产品验证的行为。
