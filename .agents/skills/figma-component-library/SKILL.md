# Figma 组件库搭建

适用于有设计稿或已有组件库的项目。颜色、字型、尺寸、主题和状态以目标项目为准。先读当前工作区规则和已有问题日志（若有），再以用户确认的定稿、设计系统及评论为证据。截图只能证明可见表现；无法读到的属性和未画出的交互分别标为「待核」与「设计补充」。

1. 搭建、整理或补齐任务先读[搭建与自验手册](references/build-workflow.md)和[组件资产准入与复用验收](references/asset-contract.md)。按「原稿与盘点 → 资产分层及依赖 → 基础规范 → 母版接口 → 新实例验证 → 场景和说明 → 全库自验」执行。只读验收不写入。
2. 布局、字体、颜色、浮层、变体切换或工具写入出现偏差时，用[常见难点与解决方法](references/troubleshooting.md)定位、修复、复验，把预防措施用于下一批组件。
3. 定稿默认只读。改母版、变量、共享样式或交互前查直接、嵌套及共享引用；不能证明修改范围安全时用独立资产，无法隔离时暂停该项。只在获授权的目标写入；搭建权限不包含发布库权限。

## 一次任务交付到可用

- **先交付资产，再证明用法。** 在全新空白验证框里，从资源中新插入一个母版实例，换成不同的业务内容或实例依赖，按有意义的宽度与状态切换，检查实例未分离、布局回流、覆写保留。绑定和覆写要分别验证。仅画板成组、原图升格为组件、实例链接存在或状态能切换，均不足以算可复用。
- 分开交付 Foundations（实际绑定变量和样式）、Components（推荐母版）、Patterns（实例组合）及 References（原稿与用例证据）。可在一页分区，但示例不能计为母版。缺属性补原资产；缺场景补预览；只有确有不同职责或独立复用时才建资产。
- 在 Figma 内交付可浏览的入口、基础规范、按组件家族组织的组件说明，以及可复制的业务场景。每组在画布上写清何时用、怎么选、限制和原稿出处，并与母版及变体同区。外部文档可以补充，不能代替画布上的用法。
- 每个主要组件家族至少进入一个真实宿主。按原稿中有意义的条件增加对照，例如窄宽、流程反馈或空态；优先示范会改变布局或操作的差异。用有母版链接的实例组成场景，标明原稿对照、设计补充和未实现行为。
- 交付前分别导出入口、各组件章节、各场景组；按首次使用路径检查能不能找对、选对、装进业务。仅有变体切换通过、无顶层重叠或链接清单，不能判定组件库通过。

- 收到「搭建／修正／补齐」后，在同一轮任务内完成盘点、写入、实例测试、导出比对、修复与复测。能从证据推断或能自行修正的事项直接处理，不把常规验收交回用户，也不为每一批修改停下来等确认。
- 大量修改按可验证的小批执行。每批读回母版及实例后再扩大；断线或超时先查已成功的节点，再补缺项。发现可复现差异就修复并重验受影响范围。两次针对同一原因的修复无进展，保留最后确认可用的版本，继续不相关工作。
- 缺文件权限、缺字体或渲染环境、定稿证据冲突等明确阻塞单列。未实际覆写过的 Text 不标通过。明确交付的是本地资产，还是已发布且在另一份文件中实际插入过的团队库；不以“可发布”冒充已发布。
